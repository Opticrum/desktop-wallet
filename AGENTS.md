## Learned User Preferences

- **`mockup/` is a frozen visual reference — never modify it.** The live frontend is `app/` (byte-for-byte port of mockup). All new UI work happens in `app/`; use `mockup/` only for reading/diffing.
- Prefer Vite + React + TypeScript for the frontend (`app/`); **Tauri 2** (`src-tauri/`) for the desktop shell; **Rust** for all wallet/chain logic.
- Keep framework scaffolding thin; spend effort on page UI/content and on the data layer (frontend → IPC → real backend).
- Brand the product as Opticrum Desktop; support Chinese/English UI with a language toggle.
- Use dual light/dark themes with the soft fintech visual language in `DESIGN.md` (**slate neutrals + teal accent**, default dark). *(Supersedes the earlier "royal blue accent" note.)*
- **No top bar.** Brand + theme + language toggles live where the design says (left sidebar brand, footer toggles). *(Supersedes the earlier "top bar" note — the redesign removed it.)*
- Detail pages replace the center panel only; `LeftSidebar` stays mounted and `RightSidebar` shows node/network context. *(Supersedes the earlier "no right sidebar" note.)*
- **Local-first desktop wallet:** no backend server for wallet/channels/node/liquidity — Rust is embedded in the Tauri host and reached via IPC (`invoke()`). The **app marketplace is the only networked part** (plain `fetch` to a remote catalog).
- **All UI changes must actively reference `DESIGN.md`.** Before editing layout, styling, copy placement, or visual hierarchy in `app/`, read the relevant sections of `DESIGN.md` and align implementation with that spec; do not rely on memory or ad-hoc guesses.

## Learned Workspace Facts

- `opticrum-wallet` is a Fiber desktop wallet + app marketplace, now a Tauri 2 desktop app: `mockup/` (frozen reference) + `app/` (live frontend) + `src-tauri/` (Rust shell).
- Dev ports: **mockup = 5173, app = 5174** (kept distinct). `npm run tauri:dev` opens the desktop window and auto-starts `app/`'s vite; `npm run mockup:dev` runs the reference in a browser.
- Tauri identity: identifier `com.opticrum.wallet`, productName "Opticrum Desktop", window min 1100×700 (desktop-only layout). Config: `src-tauri/tauri.conf.json`.
- The desktop app is **Tauri-only, real-backend** — the runtime mock layer (frontend `browserMock` + core `MockBackend`/`mock_data`) was removed. All wallet/channel/node/liquidity data flows frontend → `invoke` → `opticrum-wallet-core` real backends.
- The parent monorepo already has the Rust building blocks: `opticrum-sdk` (chain interaction, orders/matches/dashboard, generic over `T: RPC`, unsigned-tx API — no key management) and `rust-server` (HD wallet BIP39/32/44, AES-256-GCM keystore, SQLite, Fiber RPC client, chain cache) — all reusable/embeddable.
- Network overview (全网概况) lives on the node detail page, not a persistent sidebar.
- News and changelogs are center-panel pages linked from the marketplace home.
- **Node-down gating:** all node-dependent actions are disabled while the node is not up — node page 出金/入金 KPI cards (send/invoice) and the liquidity market's 发布/撤销/注入/抽离/提取 buttons. `NodeContext` is the single source for `running`/`starting` (5s `node.get_runtime` poll); components read `useNode()` and gate on `running && !starting`. `NodeControlPanel` still polls its own runtime (it drives start/stop). Disabled-state styling lives in the "Disabled node-dependent actions" block at the tail of `app/src/styles/app.css`.
- **Backend error localization:** wrong wallet password returns code `not_authorized` (core `wallet/crypto.rs`); `app/src/lib/errors.ts::commandErrorText(t, err)` maps known codes to the active locale and falls back to the raw English message. Extend the switch there for new codes instead of showing `err.message` raw.
- **Fast wallet gate:** `wallet.get_status` returns only local wallet state (`has_wallet`/`unlocked`/`address`, no chain query) — `WalletModule` gates the unlock form on it so the password field renders immediately, independent of `get_summary`'s balance query (which has a 3s timeout) and the tx trace-back. Keep slow reads out of the gate path.
- **Tray / close-to-tray:** closing the window hides it to the system tray (`src-tauri/src/tray.rs`) — the fiber node keeps running in the background. Tray menu = live node + watchtower status (5s poll) + 显示/退出; 退出 shows a bilingual risk prompt via the frontend (`TrayExitHandler`, `tray-exit-requested` event) → confirmed via `app.exit` (bypasses the close handler). Locale syncs to the shell via `app.set_locale` (from `LocaleContext`). `app.exit` must come from the frontend confirm, not direct tray-quit, or the risk warning is skipped.
- **Tray menu is built ONCE at setup; never rebuild it with `set_menu`.** The old 5s poller rebuilt the whole NSMenu from a background tokio thread (`tray.set_menu` → AppKit `setMenu:` off the main thread, racing an open menu) — that is what caused the recurring macOS crash: a Rust panic escaping tao's `sendEvent:` trampoline → `panic_cannot_unwind` → SIGABRT, usually when clicking 显示 after the app had been hidden a while. Now the poller only writes the node/watchtower result into `TrayStatusState` and, on an actual change, calls `update_tray_menu`, which updates the existing items' text via `MenuItem::set_text` (tauri marshals this to the main thread). `show_main_window` defers show/unminimize/set_focus via `run_on_main_thread` so it doesn't re-enter AppKit mid-menu-tracking. `lib.rs` installs a panic hook that appends panic+backtrace to `<app-data>/panic.log` — check that file if any macOS crash recurs. (A one-time `did_finish_launching` startup abort is the separate tao 0.35.3 / macOS 26 Tahoe issue, tauri#15517.)
- **Personal-order cache:** `liquidity.get_orders('mine')` reads the local SQLite `cached_orders` (keyed by outpoint) once a scan has primed it — loading skips the chain scan (order outpoints are immutable). `liquidity.refresh_orders` re-scans + replaces the cache; the liquidity page's refresh button calls it. Cache logic in `core/src/backend/real_liquidity.rs` + `core/src/db/orders_cache.rs`; `RealLiquidityBackend` takes an `Option<SqliteConnection>` (None in tests → always scan).
- **Order/match cell fiber-pubkey attribution + legacy flag:** `OrderArgs.fiber_pubkey` (first 33 bytes of the order cell's lock args) is the fiber NODE identity, NOT the wallet key. `publish_order` writes the current node's pubkey there (shared `Arc<Mutex<Option<String>>>` wired in `BackendBundle::real`, written by `RealNodeBackend` on start) — so orders created under an older/different node key are detectable. `LiquidityOrder`/`LiquidityMatch` now carry `fiber_pubkey` (hex, `#[serde(default)]` so pre-feature `cached_orders` rows deserialize with `""`). Frontend compares each cell's pubkey against `NodeContext.fiberPubkey` (`app/src/node/NodeContext.tsx`): mismatch → amber `!` badge on the cell + pubkey row + risk banner in the detail drawer (`LiquiditySheet.tsx`). Old orders (incl. pre-feature wallet-key cells) therefore show as legacy until a re-scan populates their real pubkey.
- **Keep-alive routing:** the node and liquidity pages stay mounted in `AppShell` (`.app-page` toggled by route via `useLocation`); their routes render `element={null}`. Switching between them never re-fetches data — but both stay mounted at startup and the node page's 5s pollers keep running in the background while hidden. Secondary pages (news/changelog/app detail) route normally through `<Outlet />`.
- **Cell physics persistence** (`LiquidityCellField`): the physics effect is rebuilt per tab (keyed on `mode`), but the tab's sim positions/velocities are saved to `savedPositions` on teardown and restored on the next visit — so switching tabs never re-scatters (only brand-new cells get placed). The rAF loop pauses via IntersectionObserver when the pool leaves the viewport (page hidden via keep-alive) and on `document.hidden`; the ResizeObserver skips clamping when the pool is hidden (size 0) so positions aren't corrupted. Original wall/collision physics (`stepSim`) is unchanged.
