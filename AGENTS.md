# AGENTS.md

## Learned User Preferences

- **`mockup/` is a frozen visual reference — never modify it.** The live frontend is `app/` (byte-for-byte port of mockup). All new UI work happens in `app/`; use `mockup/` only for reading/diffing.
- Prefer Vite + React + TypeScript for the frontend (`app/`); **Tauri 2** (`src-tauri/`) for the desktop shell; **Rust** for all wallet/chain logic.
- Keep framework scaffolding thin; spend effort on page UI/content and on the data layer (frontend → IPC → real backend).
- Brand the product as Opticrum Desktop; support Chinese/English UI with a language toggle.
- Use dual light/dark themes with the soft fintech visual language in `DESIGN.md` (**slate neutrals + teal accent**, default dark). *(Supersedes the earlier "royal blue accent" note.)*
- **No top bar.** Brand + theme + language toggles live where the design says (left sidebar brand, footer toggles). *(Supersedes the earlier "top bar" note — the redesign removed it.)*
- Detail pages replace the center panel only; `LeftSidebar` stays mounted. On `/node`, use the internal side menu + content split; open the CKB wallet as a page-level bottom drawer, not a sidebar card.
- **Local-first desktop wallet:** no backend server for wallet/channels/node/liquidity — Rust is embedded in the Tauri host and reached via IPC (`invoke()`). The **app marketplace is the only networked part** (plain `fetch` to a remote catalog).
- **All UI changes must actively reference `DESIGN.md`.** Before editing layout, styling, copy placement, or visual hierarchy in `app/`, read the relevant sections of `DESIGN.md` and align implementation with that spec; do not rely on memory or ad-hoc guesses.

## Learned Workspace Facts

- `opticrum-wallet` is a Fiber desktop wallet + app marketplace: Tauri 2 (`src-tauri/`) + live frontend (`app/`) + frozen `mockup/`. Identifier `com.opticrum.wallet`, productName "Opticrum Desktop", window min 1100×700. Dev ports: **mockup = 5173, app = 5174** (`npm run tauri:dev` auto-starts `app/`'s vite; `npm run mockup:dev` is the reference browser).
- The desktop app is **Tauri-only, real-backend** — the runtime mock layer (frontend `browserMock` + core `MockBackend`/`mock_data`) was removed. All wallet/channel/node/liquidity data flows frontend → `invoke` → `opticrum-wallet-core` real backends.
- The parent monorepo already has the Rust building blocks: `opticrum-sdk` (chain interaction, orders/matches/dashboard, generic over `T: RPC`, unsigned-tx API — no key management) and `rust-server` (HD wallet BIP39/32/44, AES-256-GCM keystore, SQLite, Fiber RPC client, chain cache) — all reusable/embeddable.
- Network overview (全网概况) lives on the node detail page, not a persistent sidebar. News and changelogs are center-panel pages linked from the marketplace home.
- **Node-down gating:** all node-dependent actions are disabled while the **active** node is not up — node page 出金/入金 KPI cards (send/invoice) and the liquidity market's 发布/撤销/注入/抽离/提取 buttons. `NodeContext` is the single source for `running`/`starting`/`fiberPubkey`/`chain` (5s `node.get_runtime` poll of the selected target); components read `useNode()` and gate on `running && !starting`. `NodeControlPanel` start/stop applies only to the built-in node. Disabled-state styling lives in the "Disabled node-dependent actions" block at the tail of `app/src/styles/app.css`.
- **Backend error localization:** wrong wallet password returns code `not_authorized` (core `wallet/crypto.rs`); `app/src/lib/errors.ts::commandErrorText(t, err)` maps known codes to the active locale and falls back to the raw English message. Extend the switch there for new codes instead of showing `err.message` raw.
- **Fast wallet gate:** `wallet.get_status` returns only local wallet state (`has_wallet`/`unlocked`/`address`, no chain query) — `WalletModule` gates the unlock form on it so the password field renders immediately, independent of `get_summary`'s balance query (which has a 3s timeout) and the tx trace-back. Keep slow reads out of the gate path.
- **Tray / close-to-tray:** closing the window hides it to the system tray (`src-tauri/src/tray.rs`) — the fiber node keeps running. Tray menu = live **built-in** node + watchtower status (5s poll) + 显示/退出; 退出 shows a bilingual risk prompt via the frontend (`TrayExitHandler`) → confirmed via `app.exit`. Locale syncs via `app.set_locale`. **Build the tray menu once at setup; never rebuild it with `set_menu`.** The old poller rebuilt the whole NSMenu off the main thread and caused the recurring macOS crash (tao `sendEvent:` → `panic_cannot_unwind` → SIGABRT). The poller only writes `TrayStatusState` and, on change, updates item text via `MenuItem::set_text`. `show_main_window` defers via `run_on_main_thread`. Panic + backtrace append to `<app-data>/panic.log`. (A one-time `did_finish_launching` startup abort is the separate tao 0.35.3 / macOS 26 Tahoe issue, tauri#15517.)
- **Personal-order cache + fiber-pubkey attribution:** `liquidity.get_orders('mine')` reads SQLite `cached_orders` (keyed by outpoint) once primed; `liquidity.refresh_orders` re-scans. `OrderArgs.fiber_pubkey` is the fiber **node** identity, not the wallet key — `publish_order` writes the current node's pubkey (shared `Arc<Mutex<Option<String>>>` from `RealNodeBackend`). Frontend compares each cell against `NodeContext.fiberPubkey`; mismatch → amber `!` badge + risk banner in `LiquiditySheet`. `#[serde(default)]` so old cache rows deserialize as `""` (legacy until re-scan).
- **Keep-alive routing + cell physics:** node and liquidity pages stay mounted in `AppShell` (`.app-page` toggled by route); their routes render `element={null}`. Secondary pages (news/changelog/app detail) go through `<Outlet />`. `LiquidityCellField` rebuilds per tab but restores `savedPositions` so tab switches never re-scatter; rAF pauses via IntersectionObserver / `document.hidden`, and ResizeObserver skips clamping when the pool is hidden (size 0).
- **Node page dual-pane + external Fiber RPC:** `/node` is left `NodeSideMenu` (~216px: prominent built-in card → inset **external-nodes panel** with the add button hugging the latest entry → wallet card at the foot) + content (console, full-width 4-KPI strip, logs only for built-in, connections). Targets persist in `node-targets.json` (`node.list_targets` / `add_external` / `update_external` / `remove_external` / `set_active`). Selecting an external hot-switches the shared Fiber RPC client so `node.*` / `channels.*` hit that target and liquidity `fiberPubkey` / `running` / `chain` follow it. Switching to external does **not** stop the built-in process; the tray still reflects only the local built-in node. External console is read-only (reachability / pubkey / address / version + edit connection; no start/stop / logs / config / fnn-cli / watchtower).
- **Wallet drawer is page-level:** node-menu「钱包」opens a `BottomDrawer` for the single local CKB wallet (independent of the selected node's funds). Layout is a real page — header (title, copyable address, lock), hero available balance (display-only) + 发送/收款 buttons, filter chips + full tx table — not sidebar-card density (no compact 4-row table, no tap-balance-to-send). Unlock uses the same page chrome. No-wallet still blocks the whole node page via `WalletSetupDialog`.
