# AGENTS.md

## Learned User Preferences

- **`mockup/` is a frozen visual reference — never modify it.** The live frontend is `app/` (byte-for-byte port of mockup). All new UI work happens in `app/`; use `mockup/` only for reading/diffing.
- Prefer Vite + React + TypeScript for the frontend (`app/`); **Tauri 2** (`src-tauri/`) for the desktop shell; **Rust** for all wallet/chain logic.
- Keep framework scaffolding thin; spend effort on page UI/content and on the data layer (frontend → IPC → real backend).
- Brand the product as Opticrum Desktop; support Chinese/English UI with a language toggle.
- Use dual light/dark themes with the soft fintech visual language in `DESIGN.md` (**slate neutrals + teal accent**, default dark). *(Supersedes the earlier "royal blue accent" note.)*
- **TopBar has no page nav.** Brand + Opticrum market chip (label only — no live numbers) + theme / language / About live in the top bar, with a bare GitHub mark to the right of About (icon only — no square chrome). Wallet CKB network is shown on the side-menu wallet row (colored ink + dot under 钱包 — not a TopBar pill); network chrome uses `--net-mainnet` (teal) / `--net-testnet` (amber) / `--net-mismatch` (danger) on network surfaces only (wallet switch, side-menu wallet net line, node net badge) — not a global brand retheme. The market chip is a teal pill, distinct from theme / language / About chrome; its hover flyout is a lifted cool-slate sheet (not `--surface`, not a teal fill that camouflages on the sea-teal inbound KPI) with a 1px teal ring matching other borders (no top stripe, no network badge). GitHub opens `https://github.com/Opticrum/desktop-wallet` via `node.openUrl`. 应用市场 / 节点 / 入金流动性 buttons are gone; `/` and `/liquidity` redirect to `/node`.
- Detail pages replace the center panel only. On `/node`, use the internal side menu + content split; open the CKB wallet as a page-level bottom drawer, not a sidebar card.
- **Local-first desktop wallet:** no backend server for wallet/channels/node/liquidity — Rust is embedded in the Tauri host and reached via IPC (`invoke()`). The **app marketplace is the only networked part** (plain `fetch` to a remote catalog).
- **All UI changes must actively reference `DESIGN.md`.** Before editing layout, styling, copy placement, or visual hierarchy in `app/`, read the relevant sections of `DESIGN.md` and align implementation with that spec; do not rely on memory or ad-hoc guesses.
- **Drawer close:** every `BottomDrawer` closes via a circular X outside the sheet (top-center on bottom sheets, vertically centered on the left edge of a right-hand column); exit animation is the reverse of enter; the backdrop does not dismiss. Cell-detail drawers have no in-sheet back button.
- **On-chain tx dialogs:** send/confirm sheets stay open after the tx lands; the user dismisses them. After confirmation, show the tx hash and make it open the explorer (wallet network, not the Fiber node network). Channel open does **not** use the CKB tx confirm dialog — after the Fiber RPC returns, wait for the channel to appear on refresh (the CKB confirm path times out).
- **Node logs vs cards:** the recent-logs strip is a recessed slate well (page-bg mixed into surface), not a matching `--surface` panel — same family, low contrast, visually a tool strip. Collapsed, it shows a truncated one-line preview of the latest log. 节点列表 | 入金流动性 section tabs are a matching recessed segmented control; the active tab uses the same solid `--accent` / white-ink prominence as 新建连接. 出入金 KPIs and channel I/O use a high-chroma pair (`--flow-out` coral-terracotta send / `--flow-in` sea-teal receive) — vivid enough to read as live on the slate page, not candy red/green, not `--danger` / `--ok`. KPI idle uses the soft wash; titles, units, labels, and icons stay on the token chroma so they read against the wash. Channel capacity feet use the same pair quieter (fill = outbound, track = inbound) — never brand blue on the capacity feet. Channel-foot press must not change size. Empty-channel **暂无通道** is an inset dashed foot with muted `--ink-4` ink and no fill — disabled-looking, not a theme-accent wash, not the I/O pair, not a solid CTA. The channel drawer's empty state has no large dashed box — header + 新建通道 only.

## Learned Workspace Facts

- `opticrum-wallet` is a Fiber desktop wallet + app marketplace: Tauri 2 (`src-tauri/`) + live frontend (`app/`) + frozen `mockup/`. Identifier `com.opticrum.wallet`, productName "Opticrum Desktop", window min 1100×700. Dev ports: **mockup = 5173, app = 5174** (`npm run tauri:dev` auto-starts `app/`'s vite; `npm run mockup:dev` is the reference browser).
- The desktop app is **Tauri-only, real-backend** — the runtime mock layer (frontend `browserMock` + core `MockBackend`/`mock_data`) was removed. All wallet/channel/node/liquidity data flows frontend → `invoke` → `opticrum-wallet-core` real backends.
- The parent monorepo already has the Rust building blocks: `opticrum-sdk` (chain interaction, orders/matches/dashboard, generic over `T: RPC`, unsigned-tx API — no key management) and `rust-server` (HD wallet BIP39/32/44, AES-256-GCM keystore, SQLite, Fiber RPC client, chain cache) — all reusable/embeddable.
- Network overview (全网概况) lives on the node detail page, not a persistent sidebar. Opticrum **market** overview is the TopBar `MarketOverviewChip` (label only — no live numbers; hover to read, click to refresh; dashboard data loads on hover, not on page load) and **follows the wallet CKB network** (`WalletNetworkContext` → `setMarketDashboardChain`). On mainnet, the market chip/flyout and node-page liquidity panel show 主网暂未开放 / `lmMarketUnavailableTitle` and skip Opticrum contract scans. Inbound liquidity is a node-page section tab (below recent logs, above the connection list) — not a standalone route; the old liquidity-page `lm-dash` aside is gone. News and changelogs are center-panel pages linked from the marketplace home.
- **Node-down + network-mismatch gating:** all node-dependent actions are disabled while the **active** node is not up — node page 出金额度/入金额度 KPI cards (send/invoice) and the node-page liquidity tab's 发布/撤销/注入/抽离/提取 buttons. `NodeContext` is the single source for `running`/`starting`/`fiberPubkey`/`chain` (5s `node.get_runtime` poll of the selected target); components read `useNode()` and gate on `running && !starting`. When the active node is `running && node.chain !== wallet.chain` (wallet chain from `WalletNetworkContext`), mismatch UI applies (danger-styled net badge + hover tip; red `!` on the selected `NodeSideMenu` card) and on-chain actions stay blocked (send/invoice, open/close channel, liquidity publish/cancel/inject/withdraw/extract); read-only node views, logs, start/stop, config, and connection management remain available. `NodeControlPanel` start/stop applies only to the built-in node. Disabled-state styling lives in the "Disabled node-dependent actions" block at the tail of `app/src/styles/app.css`.
- **Backend error localization:** wrong wallet password returns code `not_authorized` (core `wallet/crypto.rs`); `app/src/lib/errors.ts::commandErrorText(t, err)` maps known codes to the active locale and falls back to the raw English message. Extend the switch there for new codes instead of showing `err.message` raw.
- **Fast wallet gate:** `wallet.get_status` returns only local wallet state (`has_wallet`/`unlocked`/`address`, no chain query) — `WalletModule` gates the unlock form on it so the password field renders immediately, independent of `get_summary`'s balance query (which has a 3s timeout) and the tx trace-back. Keep slow reads out of the gate path. A balance timeout must not present as 0 — keep the loading ellipsis. Fetch the tx list after balance, not in parallel. Pause the inbound-liquidity chain scan while the wallet drawer is open.
- **Tray / close-to-tray:** closing the window hides it to the system tray (`src-tauri/src/tray.rs`) — the fiber node keeps running. Tray menu = live **built-in** node + watchtower status (5s poll) + 显示/退出; 退出 shows a bilingual risk prompt via the frontend (`TrayExitHandler`) → confirmed via `app.exit`. Locale syncs via `app.set_locale`. **Build the tray menu once at setup; never rebuild it with `set_menu`.** The old poller rebuilt the whole NSMenu off the main thread and caused the recurring macOS crash (tao `sendEvent:` → `panic_cannot_unwind` → SIGABRT). The poller only writes `TrayStatusState` and, on change, updates item text via `MenuItem::set_text`. `show_main_window` defers via `run_on_main_thread`. Panic + backtrace append to `<app-data>/panic.log`. (A one-time `did_finish_launching` startup abort is the separate tao 0.35.3 / macOS 26 Tahoe issue, tauri#15517.)
- **Personal-order cache + fiber-pubkey attribution:** `liquidity.get_orders('mine')` reads SQLite `cached_orders` (keyed by outpoint) once primed; `liquidity.refresh_orders` re-scans. `OrderArgs.fiber_pubkey` is the fiber **node** identity, not the wallet key — `publish_order` writes the current node's pubkey (shared `Arc<Mutex<Option<String>>>` from `RealNodeBackend`). The node-page liquidity tab filters cells with `sameFiberPubkey` against `NodeContext.fiberPubkey` (empty / legacy `""` pubkey matches no node). Residual mismatch still shows an amber `!` badge + risk banner in `LiquiditySheet`. After the grace period, 可抽离 still shows `0 CKB` (muted) with a 犹豫期已过 tip on the right — do not shift 可提取. `#[serde(default)]` so old cache rows deserialize as `""` (legacy until re-scan).
- **Keep-alive routing + cell physics:** the node page stays mounted in `AppShell` (`.app-page` toggled by route; `/node` renders `element={null}`). Secondary pages (news/changelog/app detail) go through `<Outlet />`. On the node page, 节点列表 / 入金流动性 section tabs keep both panes mounted (`display: none` when inactive) so `LiquidityCellField` does not re-scatter; rAF pauses via IntersectionObserver / `document.hidden`, and ResizeObserver skips clamping when the pool is hidden (size 0).
- **Node page dual-pane + external Fiber RPC:** `/node` is left `NodeSideMenu` (~216px: prominent built-in card → inset **external-nodes panel** with the add button hugging the latest entry → wallet card at the foot) + content (monitor card + 2×2 KPI cluster titled 出金额度/入金额度/节点数/通道数 beside it, logs only for built-in, then section tabs **节点列表 | 入金流动性**). 节点列表 is the peer connection grid; 入金流动性 is `NodeLiquidityPanel` (cell pool as the large background; order/match controls float on the field, not a topbar; filtered by the selected node's pubkey; **购买流动性** + refresh sit outside on the right in the same slot as 新建连接; cell click opens a right `BottomDrawer` with a smooth slide — no jump, no hover tooltip while open). Opticrum market overview is the TopBar chip. Dashboard is chain-scan, not gated on node-up. Connections are a **2-column** grid of peers; each peer is a header card (identity / endpoints / actions) plus a flush foot button whose background is a **progress bar** of this-side capacity / total. The foot opens `ChannelListDrawer` — a full-height right column (~560px, slightly wider than a node card) with a compact header (pubkey, version, inbound/outbound), stacked channel **gauges** (capacity, no fee row), and a low-prominence dashed **暂无通道** (muted ink, disabled-looking, not 出入金; in-page, not a modal). Not accordion, nested cards, or tables. Targets persist in `node-targets.json` (`node.list_targets` / `add_external` / `update_external` / `remove_external` / `set_active`). Selecting an external hot-switches the shared Fiber RPC client so `node.*` / `channels.*` hit that target and liquidity `fiberPubkey` / `running` / `chain` follow it. Switching to external does **not** stop the built-in process; the tray still reflects only the local built-in node. External console is read-only (reachability / pubkey / address / version + Fiber 端口 = creation RPC URL, click opens fnn-cli + edit connection; no start/stop / logs / config / watchtower).
- **Wallet drawer is page-level:** node-menu「钱包」shows lock vs unlock via **border color** (warn / ok, no badge); the sub-line is the wallet CKB network (colored ink + dot: 主网 / 测试网), not lock copy. Locked click opens `WalletUnlockDialog` (not mixed into the drawer); success then opens the `BottomDrawer`. Unlocked click opens the drawer directly. Drawer is a real page for the single local CKB wallet (independent of the selected node's funds) — header (title, copyable address, **主网/测试网** segmented switch; **no lock button**), hero available balance (display-only) + 发送/收款, filter chips + full tx table — not sidebar-card density. No-wallet still blocks the whole node page via `WalletSetupDialog`. **Wallet CKB network ≠ Fiber node network:** `WalletNetworkContext` + `wallet.set_network` own the app-level CKB chain; core `NetworkController` hot-swaps prebuilt mainnet/testnet RPC/indexer clients without stopping Fiber or re-entering the mnemonic — same BIP44 keys, re-encode `ckb1…` / `ckt1…` only; tx/order SQLite caches are chain-partitioned. Fiber node chain stays on `NodeContext` / node targets independently.
